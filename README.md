# Feel My Heartbeat

只有两个人的房间。你点一下，两边的爱心一起冒。

零依赖，只用 Node.js 内置模块。两个文件就是全部：`server.js` 和 `index.html`；
另有一个 `debug.html`，是单独隔离的只读调试台（`/debug`），排查时才用得上，删了主页面照样跑。

调试还有一个 `/test`：同一个页面、同一套代码，但进的是服务端内存里的另一个房间 ——
在那儿怎么点都不写 `hearts.json`、不写 `history/`，跟真房间里的人互相看不见。

下面命令里的 `<项目目录>` 指 `server.js` 所在的那个文件夹。

---

## 这台机器上跑着什么

想让对方能连上，这台机器上要同时跑着两个东西，缺一不可：

| 角色 | 是什么 | 命令 | 端口 |
|------|--------|------|------|
| **服务器** | Node 网站本体，存心跳、发纸条 | `node server.js` | 本机 `8787` |
| **Cloudflare 隧道** | 把本机 8787 端口暴露到公网，给你一个 `https://xxx.trycloudflare.com` 网址 | `cloudflared tunnel --url http://localhost:8787` | — |

房间口令（ROOM_KEY）：写在项目根目录的 `.env` 里（不进仓库），对方打开网址后要输入它才能进房间。
下面命令里出现的 `123456` 都是占位的示例口令，换成你自己的。

> ⚠️ 现在用的是**临时隧道（quick tunnel）**。它最大的特点：**每次重启 cloudflared，网址都会变一个新的。** 重启完记得把新网址发给对方。
>
> ⚠️ **放到公网之前一定要改掉默认口令。**

## 跑起来

服务器负责数据。改了 `server.js`、或者它崩了，就重启它。

```bash
# 1) 先关掉旧的
pkill -f "node server.js"

# 2) 进目录，带着口令重新启动
cd <项目目录>
ROOM_KEY=123456 PORT=8787 node server.js
```

启动成功会看到「Feel My Heartbeat」和版本号，以及累计心跳、同频次数，日志里也会打印本机地址和局域网地址。
数据都存在同目录的 `hearts.json`，重启不会丢。

打开 `http://localhost:8787`，填名字和口令进去。

**想让它在后台一直跑、关掉终端也不停：**

```bash
cd <项目目录>
ROOM_KEY=123456 PORT=8787 nohup node server.js > server.log 2>&1 &
```

之后看日志：`tail -f server.log`（在项目目录下）

## 让朋友连上

推荐 Cloudflare Tunnel，免费、不用买服务器、不用开路由器端口。
网址打不开、或者你重启了服务器，就重启隧道：

```bash
# 1) 关掉旧隧道
pkill -f "cloudflared tunnel"

# 2) 重新开一个，指向本机 8787
cloudflared tunnel --url http://localhost:8787
```

启动后屏幕上会刷出一大段，找这样一行框起来的网址：

```
+--------------------------------------------------------+
|  https://随机单词-随机单词.trycloudflare.com            |
+--------------------------------------------------------+
```

**这就是新网址，复制它发给对方。**

**想让它在后台跑、并且把网址记到文件里：**

```bash
cd <项目目录>
nohup cloudflared tunnel --url http://localhost:8787 > tunnel.log 2>&1 &

# 等几秒，把网址捞出来
sleep 6 && grep -o 'https://.*trycloudflare.com' tunnel.log | head -1
```

**重启 node 不需要重启 cloudflared**，隧道只认端口不认进程。

临时隧道每次重启都换网址。想要固定网址，注册域名接到 Cloudflare，再建命名隧道（`cloudflared tunnel create` → `route dns`）。

### 对方怎么用

1. 确认两个进程都在跑（见下方「检查现在跑没跑」）。
2. 拿到当前的 `https://xxx.trycloudflare.com` 网址。
3. 把**网址**和**口令 `123456`** 发给对方。
4. 对方用手机／电脑浏览器打开网址，输入口令，就进房间了。
5. 你自己也打开同一个网址、同一个口令，两个人就连上了。

> 房间最多 8 个连接（`MAX_CLIENTS`），够两个人来回刷新用。满了会把最久没动静的那条挤掉。

```bash
# 看两个进程在不在
ps aux | grep -E "server.js|cloudflared tunnel" | grep -v grep

# 看 8787 端口有没有在监听
ss -tlnp | grep 8787

# 本机自测网站（返回 HTML 就对了）
curl -s localhost:8787 | head -1
```

两个进程都在、端口在监听，就是正常的。

## 版本管理

版本号是 主版本.次版本.修订号，前后端共用一个号。

**次版本号要攒够几个小更新才动。** 一般的新增功能、修 bug、调格式，都只加修订号。
比语义化版本保守一些。

**版本号不写进 commit title**，改动写清楚做了什么就行。

**只给次版本及以上打 tag**（`v1.1.0`、`v1.2.0`、`v2.0.0`）。修订号那一层不打 ——
改动看 commit 就够了，不必在 tag 列表里占位：

```bash
# 升到次版本时才打
git tag -a v1.2.0 -m "..." && git push origin v1.2.0

git tag -n1          # 看所有已发布版本
```

**版本号写在三个地方，改的时候三处都要改：**

1. `package.json` 的 `version` 字段（唯一来源，服务端优先读它）
2. `server.js` 顶部的 `let VERSION`（读不到 package.json 时的兜底）
3. `index.html` 里的 `const VERSION`

**三道自动检查：**

- **启动时**：服务端会读 `index.html` 比对版本，不一致就在日志里警告
- **登录时**：前端向 `/check` 要服务端版本，对不上直接拦在登录页，提示「服务端是 X，前端是 Y」
- **重连时**：`welcome` 事件带着服务端版本，对不上就停掉轮询，顶栏显示「服务端已更新到 X，请刷新页面」

这三道检查是从实际踩坑里来的 —— 更新时只换了一个文件、或者忘了重启，表现出来是各种莫名其妙的连接故障，很难排查。

第三道针对的是：**页面一直开着没关，服务端在这期间升级了。** 登录检查只在进门时跑一次，
挡不住这种情况；旧页面会带着旧代码继续轮询，可能根本处理不了新事件，表现成
「对方明明在线、消息也发了，我这边什么都没有」，而服务端日志和 `history/` 里一切正常。
改完 `index.html` 后记得让两边都刷新一次页面（`Ctrl+Shift+R`）。

改动记在 `CHANGELOG.md`。

## 排查

**看服务器眼里现在有谁**

```bash
curl "http://localhost:8787/who?key=你的口令"
```

返回连接数、每个人的名字、连了多久、多久没动静、有没有挂着的请求，
以及这条连接是从哪个网址进来的、什么浏览器、页面是哪个版本 ——
在线名单里多出一台说不清是谁的时候，看这几项就能认出是哪台设备上的哪个页面。

**清空统计**（调试数据积多了）

```bash
curl -X POST "http://localhost:8787/reset?key=你的口令"
```

**测试房间 `/test`**

网址后面加 `/test`（`http://localhost:8787/test`），出来的是**一模一样的页面** ——
同一个 `index.html`，同一套代码，只是它进的是服务端内存里的另一个房间：

- 统计不落盘、纸条不写 `history/`，服务端一重启这个房间就干净了
- 跟真房间完全隔开：你在 `/test` 里点心跳、发纸条，TA 那边什么都感觉不到，
  在线名单里也不会多出一个人
- 顶栏左边有个金色的「测试房间」标签，整块屏幕描一道淡金边框，标题也变成
  「测试房间」—— 免得调着调着忘了自己在哪
- 音乐还是共用 `music/` 那个文件夹（只读，放歌不会改到任何东西）

**一键同频模式**（只有 `/test` 有）

`/test` 顶栏上多一颗「同频模式」。按一下，服务端往这个测试房间里塞一个
不需要浏览器的假 TA（名字就叫「测试的 TA」）：

- 它在在线名单里，所以页面立刻就是「两个人都在」—— 背景冒小爱心、音乐放起来、
  同在开始计时
- 你点一下心跳，它会在同频窗口内跟着点一下，两边一起爆金色 ——
  真房间里「刷不出来」的同频，在这儿一按就有
- 按住连发时它不会每一下都跟，攒够 2.5 秒才回一次，免得同频刷屏
- 再按一下送走它

命令行也行，真房间不给动（返 403）：

```bash
curl -X POST "http://localhost:8787/bot?key=你的口令&room=test&on=1"
```

**调试台**

浏览器打开 `http://localhost:8787/debug`，输一遍口令（主页面登录过的浏览器会自动带上，
也可以直接 `/debug?key=你的口令`，口令进页面后当场从地址栏抹掉）。

它跟主页面是**完全分开的两页**，而且只看不动：不进房间、不算在线人数、
不会拿走攒着的心跳和纸条，页面上也没有任何能改到房间的按钮 —— 拿它盯着，
不会在 TA 那边多出一个人，也不会往统计里加数。

一页看全服务端此刻的样子，每 2 秒重读一次（可暂停）：

- **在线连接**：几台、每台什么设备什么浏览器、页面哪版、连了多久、多久没动静、
  有没有挂着的请求、队列里压着几条、从哪个网址进来、来源 IP、设备号、连接 id
- **刚被顶掉的**：id、原因（`replaced` 被同设备顶掉 / `stale` 页面版本不对）、多久前 ——
  「怎么又多出一台」「怎么自己被踢了」看这里
- **计数**：今天／累计各人多少下、同频几次、上一次心跳是谁多久前（还在不在同频窗口内）、
  存档文件多大存于何时、Node 版本和内存
- **攒着没送出去的**：等着交给对方的心跳数和纸条
- **纸条记录**：选日期看当天全部纸条，最新那天会自动跟进（见「聊天记录」）
- **music 文件夹**：服务端认出来的曲目
- **服务端参数**：几台上限、同频窗口、纸条上限、超时……代码里那些常量
- **原始 /state**：整包 JSON 摊开

顶栏那颗「看：真房间／test 房间」切的是看哪个房间 —— 在 `/test` 里点心跳，
得切到 test 房间才看得见。

命令行要同一份数据：`curl "http://localhost:8787/state?key=你的口令"`，
加 `&room=test` 看测试房间。`/who`、`/reset` 也认这个参数。

**常见情况**

| 症状 | 多半是 | 怎么办 |
|---|---|---|
| 对方说网址打不开 | 隧道网址变了（重启过），或隧道没跑 | 按「让朋友连上」重开，发新网址 |
| 能打开但进不去房间 / 提示口令不对 | 口令要一字不差 | 确认是 `123456` |
| 能打开但没有实时同步、心跳不动 | 服务器（node）没跑 | 按「跑起来」重启 |
| 登录页提示版本不一致 | 只换了一个文件，或者没重启 node | 三处版本对齐后重启 node |
| 两个人互相看不见 | 名字填成一样了 —— 按名字认人，同名会被当成同一个人 | 换个不一样的名字 |
| 改完 `server.js` 没生效 | node 要重启才会加载新代码 | 重启 node；改 `index.html` 前端不用重启，对方刷新即可 |
| 一直显示重连中 | 服务器没跑，或者隧道断了 | 检查两个进程 |
| 延迟高 | 隧道线路本身的往返时间 | 换命名隧道或 VPS 直连 |
| 数据不见了 | 没在同一个目录启动 | 检查 `hearts.json` 还在不在、是不是在同目录启动 |

## 通信

HTTP 长轮询。四个接口：

- `POST /join` 进房间拿 id
- `GET /poll` 取消息，有货立刻回，没货挂住最多 25 秒
- `POST /send` 发消息
- `POST /leave` 关页面时立刻下线

上面五个接口都认一个可选的 `room=test`，带上就走内存里那个测试房间
（`/test` 那一页发的每个请求都带着它），不带就是真房间。

另有几个带口令的辅助接口，除了 `/reset` 和 `/bot` 全是 GET 只读：
`/state` 服务端此刻的全貌（`/debug` 那一页就是它渲染出来的）、
`/who` 看在线情况、`/reset` 清统计、`/history` 取聊天记录、
`/music/list` 拿曲目清单、`/music/file` 放歌（支持 Range，能拖进度、Safari 也认）、
`/bot` 往测试房间叫来／送走那个假 TA。
另外 `/debug` 是调试台那一页，`/test` 是测试房间那一页（送的就是 `index.html`）。

之所以是长轮询而不是更时髦的方案：SSE 经 Cloudflare 隧道会被缓冲，消息一阵一阵地到；WebSocket 的 upgrade 请求隧道压根不转发，握手直接失败。长轮询每次都是完整的短请求，没有需要保持的流，任何代理都拦不住。

细节见 `CHANGELOG.md` 里的早期迭代记录。

## 同在时的音乐

歌放在 `music/`，扔进去就行，加歌不用重启（每次要清单都是现读文件夹）。
两个人都在线的时候随机挑一首放，一首完了接下一首，人一走慢慢淡掉。

认得的后缀：`.mp3` `.m4a` `.aac` `.ogg` `.oga` `.opus` `.wav` `.flac` `.webm`。
最稳的是 mp3 和 m4a，什么浏览器都放得出来。以 `.` 开头的文件跳过。

音频文件不进 git（`.gitignore` 里只放行 `music/README.md`）。

```bash
# 服务器认出几首
curl "http://localhost:8787/who?key=你的口令" | grep 曲目数

# 曲目清单
curl "http://localhost:8787/music/list?key=你的口令"
```

浏览器要求页面被点过才肯出声。正常从登录页「进入」就算点过；万一被拦下，
♫ 会提示「点一下心跳，音乐就开始」，点一下大爱心就接上了。

正在放什么显示在 ♪ 左边：曲名（不带扩展名）＋ 时间，进度不另画一条，
直接把那块药丸的底色从左往右铺过去。没在放就不显示。

顶栏在窄屏（≤560px）挤不下四样东西，所以手机上：在线名单换成短的那版
（「TA 03:21」）、总时长收起来只留已播时间、`悬浮窗` 按钮不显示
—— 手机浏览器根本没有 documentPictureInPicture，按了也只是弹一句「不支持」。

## 聊天记录

纸条会存在 `history/` 下，一天一个文件，文件名是当天日期：

```
history/20260727
```

一行一条 JSON（JSON Lines），追加写入，服务端不读回内存，攒多了也不吃内存：

```
{"t":1785123319008,"name":"yuang","text":"想你了"}
```

`t` 是 Unix 毫秒时间戳。存这个而不是存可读时间，是因为它无歧义：排序、算时长、
换时区都靠它。要给人看的时候再转。

**怎么看**

打开 `/debug` 调试台，「纸条记录」那一段：上面选日期，下面按
`yymmdd 时:分:秒　名字　内容` 列出来。看的是最新那天就自动跟进，
翻旧日期时不打扰；一天几千条时只画最后 300 条，免得页面卡住。

```
260727 14:26:01  yuang  想你了
```

也可以直接用命令行。接口会在 `t` 之外额外附一个转好的 `time` 字段，
文件里不存这个：

```bash
# 有哪几天的记录
curl "http://localhost:8787/history?key=你的口令"

# 看某一天
curl "http://localhost:8787/history?key=你的口令&date=20260727"
# {"t":1785123319008,"time":"260727 11:35:19","name":"yuang","text":"想你了"}
```

要删记录直接删文件：`rm history/20260727`。`/reset` 只清统计，不动记录。

> `history/` 和 `hearts.json` 一样在 `.gitignore` 里，不进仓库。
